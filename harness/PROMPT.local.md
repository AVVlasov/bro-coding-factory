# Итерация цикла, локальный профиль

Контекст свежий, память на диске. За один ход делаешь **один шаг** и заканчиваешь ответ.
Работаешь из корня репозитория, пути только относительные.

## 1. Прочитай ровно три файла

1. `.bcf/STATE.md`: итог прошлой итерации. Блок `BACKPRESSURE` исправляй первым.
   Блок `<anti-patterns>` это уроки памяти по этой задаче: не повторяй их.
2. `tasks/CURRENT-FOCUS.md`: строка `Task file:` даёт путь к файлу задачи.
3. Файл задачи целиком. Секция «Файлы» это весь твой объём: правишь только эти файлы.
   Секция «Готовность» и «Проверки» это чем доказать.

Если есть `tasks/.verdicts/<ID>.md` с `verdict: FAIL`, его `remediation:` это список работ.
С `verdict: PASS` ничего не делай.

## 2. Сделай один шаг

Выбери первый незакрытый пункт «Готовности» и сделай для него одну правку в файлах из
секции «Файлы»: создай или измени код, добавь тест. Не изучай репозиторий шире, чем нужно
для этой правки: открывай только файлы из секции «Файлы» и те, что они импортируют.

Запрещено:
- `Get-ChildItem -Recurse`, `dir /s`, `find` по всему дереву; для поиска только `Grep` и `Glob` по конкретному каталогу;
- запускать `harness/*.ps1` и скрипты памяти руками;
- править файлы вне секции «Файлы» и менять `tsconfig`, `package.json`, конфиги;
- писать «выполнено» без `verdict: PASS`.

## 3. Проверь свою правку

Запусти команды из секции «Проверки» задачи (сборка, тест). Красное чини в этой же
итерации, если укладываешься; иначе оставь как есть, раннер вернёт ошибку в `STATE.md`.

## 4. Попроси верификацию, когда проверки зелёные

Создай файл `.bcf/VERIFY-REQUEST`:

```
task: <ID>
testers: architecture
checks: <команда из секции «Проверки»>
visual: no
```

Раннер сам прогонит тестеров и судью и запишет `tasks/.verdicts/<ID>.md`.
Итерация без правок и без `VERIFY-REQUEST` считается пустой; три пустых подряд
останавливают задачу.

## 5. Отчёт

Три строки: что изменил (файлы), что запустил (команда и код возврата), что дальше.
Не жди «продолжай»: следующую итерацию запускает раннер.
