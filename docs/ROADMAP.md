**M-05, история ревью.** Пять кругов, каждый закрыт до следующего и доказан мутацией
в сюите install-secrets.

1. Путь к bash без кавычек — команда хука не запускалась ни на одном из 15 хуков при
   пробеле в `Program Files`.
2. `git commit -a`/`-am` обходил сканер секретов. Содержимое CI-workflow не проверялось
   ни одной сюитой.
3. `git add ... && git commit ...` в одной строке обходил сканер. Правило "присвоение
   секрета" блокировало код, который уже читает секрет из окружения. `bcf init`
   отчитывался нулём при отказе `install`.
4. Кириллическое имя файла обходило сканер — `git ls-files` и `git add --dry-run`
   квотировали не-ASCII имя по-разному. `cd <каталог>` перед `git add` не учитывался при
   поиске pathspec. Отсутствие python в системе выключало хук молча.
5. При `git add ... && git commit` хук сканировал ПОЛНЫЙ дифф рабочего дерева, а не
   только пути, которые эта команда реально добавляет, — секрет в постороннем
   отслеживаемом файле блокировал чужой чистый коммит. Текст отказа всегда советовал
   `git restore --staged <файл>`, хотя для находки из рабочего дерева (не только что
   застейдженной этой командой) снимать в индексе нечего. Смешанные алфавиты в слове
   "дифф" в двух файлах документации. Граница защиты (файл, созданный в той же
   командной строке, не виден `PreToolUse`) не была названа в `docs/SETUP.md`.

## Открыто после слияния

Строки ниже не задачи, а границы того, что проверено.

- Боевого прогона с платными моделями не было ни у одной полосы: граф, память и приёмка
  доказаны фикстурами и подставными агентами. Первая ночь на настоящем бэкенде остаётся
  первой проверкой сквозного пути.
- `bcf memory init` на живом pgvector не запускался: миграция доказана разбором SQL и
  подставным psycopg, который пишет ровно те `ALTER` и `ON CONFLICT`, что ушли бы в базу.
  Один раз выполнить на существующей базе и увидеть строку «схема применена (init.sql)».
- Контракт общей памяти проверен подставным скриптом: бинаря `eog` на машине нет. Что
  настоящий `eog memory context` печатает текстовый блок или «заметок по теме нет» —
  на стороне eog.
- `harness/loop.ps1:333` по-прежнему открывает модальное окно в одиночном цикле. В
  `run-all.ps1` окна больше нет, правка одиночного цикла однострочная и не сделана.
- Последовательный путь `run night` (`limits.taskConcurrency = 1`) вердикт не коммитит:
  ветки задачи там нет, вердикт уезжает в git вместе с кодом задачи, когда коммитит
  человек. Обещание «вердикт коммитится» автоматически выполняется на параллельном пути
  и в графе.
- `Publish-TaskVerdict` и граф очереди берут путь `tasks/.verdicts` жёстко, а не из
  `paths.verdicts`.
- Доезд `graph_hash` через `BCF_GRAPH_FILE` на три уровня процессов вниз живым прогоном
  не проверен: граф запускает `loop.ps1` через `Start-Process`, тот запускает
  `verify.ps1`, и увидеть это можно только на боевом прогоне графа.

лежат в `tasks/` своего репозитория.
