# Дорожная карта фабрики

Задачи ниже меняют движок и шаблоны фабрики. Каждая закрывается живым прогоном и своей
сюитой в `tests/all.ps1`, а не описанием. Оценки в часах работы человека с агентом.

## Закрыто

| Задача | Что изменилось | Слито |
|---|---|---|
| M-01 Фабрика водит Java | `detect` узнаёт Maven, пресет `require-tests` считает пройденные тесты по XML surefire, хуки и шаблоны под Java и Liquibase, backpressure читается из `config/harness.json` | 2026-09-04, сюиты maven-runner 24 и java-hooks 61 |
| M-02 Исполнитель как поле задачи | строки `Исполнитель:` и `Блокер:` в шапке задачи; задачи с исполнителем-человеком `run night` и `run queue` в очередь не берут; `bcf task new --for` | 2026-09-04, сюита executor-field 21 |
| M-04 Честность вердикта | гейт на слитом дереве с четырьмя исходами вместо fail-open, защита `config/` и `tasks/` от правок агента, без модальных окон, `doctor` проверяет состояние git | 2026-09-04, сюита verdict-honesty 58 |
| M-05 Сервер и CI | Память проекта одна на команду. Реестр агентских слотов один на установку фабрики. Порт памяти — из машины, адрес — из проекта. `bcf init`/`install` подставляют bash полным путём в кавычках, без него отказывают вместо голого `"bash"`. `secret-scan.sh` перед коммитом блокирует похожее на ключ доступа и закрывает обходы через флаги коммита, связку `git add && git commit` и смену каталога перед ней; дифф рабочего дерева при `git add` ограничен путями, которые реально добавляет команда, а не всем репозиторием; текст отказа советует по месту находки (индекс vs рабочее дерево). `doctor`/README требуют Windows. CI на `windows-latest` гоняет `tests/all.ps1` на push и pull request. История ревью — строкой ниже. | 2026-09-06, сюиты memory-team 68 и install-secrets 106 |

**M-05, история ревью.** Пять кругов, каждый закрыт до следующего и доказан мутацией
в сюите install-secrets.

1. Путь к bash без кавычек — команда хука не запускалась ни на одном из 15 хуков при
   пробеле в `Program Files`.
2. `git commit -a`/`-am` обходил сканер секретов. Содержимое CI-workflow не проверялось
   ни одной сюитой.
3. `git add ... && git commit ...` в одной строке обходил сканер. Правило "присвоение
   секрета" блокировало код, который уже читает секрет из окружения. `bcf init`
   отчитывался нулём при отказе `install`.
4. Кириллическое имя файла обходило сканер — `git ls-files` и `git add --dry-run`
   квотировали не-ASCII имя по-разному. `cd <каталог>` перед `git add` не учитывался при
   поиске pathspec. Отсутствие python в системе выключало хук молча.
5. При `git add ... && git commit` хук сканировал ПОЛНЫЙ дифф рабочего дерева, а не
   только пути, которые эта команда реально добавляет, — секрет в постороннем
   отслеживаемом файле блокировал чужой чистый коммит. Текст отказа всегда советовал
   `git restore --staged <файл>`, хотя для находки из рабочего дерева (не только что
   застейдженной этой командой) снимать в индексе нечего. Смешанные алфавиты в слове
   "дифф" в двух файлах документации. Граница защиты (файл, созданный в той же
   командной строке, не виден `PreToolUse`) не была названа в `docs/SETUP.md`.
