# Дорожная карта фабрики

Задачи ниже меняют движок и шаблоны фабрики. Каждая закрывается живым прогоном и своей
сюитой в `tests/all.ps1`, а не описанием. Оценки в часах работы человека с агентом.

## Закрыто

| Задача | Что изменилось | Слито |
|---|---|---|
| M-01 Фабрика водит Java | `detect` узнаёт Maven, пресет `require-tests` считает пройденные тесты по XML surefire, хуки и шаблоны под Java и Liquibase, backpressure читается из `config/harness.json` | 2026-09-04, сюиты maven-runner 24 и java-hooks 61 |
| M-02 Исполнитель как поле задачи | строки `Исполнитель:` и `Блокер:` в шапке задачи; задачи с исполнителем-человеком `run night` и `run queue` в очередь не берут; `bcf task new --for` | 2026-09-04, сюита executor-field 21 |
| M-04 Честность вердикта | гейт на слитом дереве с четырьмя исходами вместо fail-open, защита `config/` и `tasks/` от правок агента, без модальных окон, `doctor` проверяет состояние git | 2026-09-04, сюита verdict-honesty 58 |
| M-03 Фабрика в команде | вердикты, заявки и доска задач (`tasks/STATUS.json`) живут в git; прогон начинается с `fetch` и fast-forward `integration.branch`, разошедшиеся ветки останавливают прогон вместо молчаливого слияния; работа уходит веткой `bcf/wave/<дата-время>` и уезжает в `publish.remote`, отказ отправки — в `needs_human`; `bcf task new` учитывает номера, занятые на remote | 2026-09-05, сюиты team-bus 31 и team-claims 30 |
| M-06 Приёмка лидерами, отчёт, трейлеры | `bcf task accept` пишет и коммитит `tasks/.acceptance/<TASK>.md`; классы CORE/NFR (`Класс:` в шапке задачи, без строки — CORE) без приёмки не продвигаются — на графе очереди и параллельном планировщике слияние отказывает с причиной «ждёт приёмки лидера», на последовательном `run night` (`limits.taskConcurrency <= 1`, отдельной ветки задачи там нет) тот же гейт не пускает git, а не даёт задаче засчитаться закрытой волной; GEN сливается по одному PASS; переписанный вердикт делает sha приёмки устаревшим — `bcf task show` показывает это явно; коммиты фабрики (граф очереди, параллельный планировщик `scheduler.ps1` при `limits.taskConcurrency > 1`, заявка на файлы и её снятие, парковка правок владельца, публикация вердикта FAIL, доска задач `Publish-TaskStatus`/`Complete-TeamRun`) несут трейлеры `Task:`/`Run-Id:`/`Role:`/`Model:`/`Backend:` и подписываются именем из `author.*`; `bcf report --export <yyyy-MM>` собирает `docs/reports/<yyyy-MM>.md` из вердиктов, приёмок, журналов графа и незакрытых задач последнего ночного прогона (`.bcf/run-all.status.json`, включая проекты без `bcf migrate` — старый каталог `loop/`); каждый вердикт несёт `factory_version:` и `graph_hash:`; `bcf help` называет `task accept` и `report --export` | 2026-09-06, сюита acceptance-report 51 (были 21 — три круга проверки добавили негативные случаи на scheduler.ps1 и граф очереди, устаревание приёмки, источник `run-all.status.json` и старый `loop/`, трейлеры вердикта/парковки/заявки/доски задач, гейт приёмки на последовательном `run-all.ps1`, справку `bcf help`) |
