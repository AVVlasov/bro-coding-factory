# /verify

Просит обвязку прогнать верификацию текущей задачи. Вердикт PASS/FAIL считает НЕ агент:
он вычисляется детерминированно по зелёным гейтам. Эта команда только формирует план и
кладёт маркер.

## Когда звать

Когда выполнены ВСЕ условия из секции «Готовность» файла задачи — и ты можешь назвать
команду, доказывающую каждое. Не «кажется, готово»: маркер, поставленный на недоделанной
работе, стоит полного прогона верификации впустую.

## Что сделать

1. Прочитай `tasks/<ID>-*.md` → «Готовность» и «Проверки».
2. Прочитай `config/harness.json` → `backpressure`, `tests`; `config/checks.json` →
   обязательные проверки задачи.
3. Запиши маркер `.bcf/VERIFY-REQUEST`:

```
task: <ID>
checks:
  - <команда 1>
  - <команда 2>
testers:
  - <роль тестера, если нужна: api | architecture | performance | ux-vision>
```

Обвязка ОБЪЕДИНИТ этот список с обязательными проверками из `config/checks.json` —
убрать их из плана нельзя, и пытаться не нужно.

## Чего не делать

- Не сужать план до одной быстрой проверки, чтобы «побыстрее получить PASS». Обязательные
  проверки всё равно подмешаются, а сузивший план агент просто теряет итерацию.
- Не вписывать в `checks` команду, которой нет в проекте: она упадёт, и вердикт будет
  FAIL по причине, не имеющей отношения к задаче.
- Не объявлять задачу закрытой самому. Закрытая задача — это `verdict: PASS` в
  `tasks/.verdicts/<ID>.md`, и пишет его обвязка.
