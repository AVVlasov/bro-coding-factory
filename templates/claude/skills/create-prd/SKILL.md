# Create PRD — из короткого запроса в спецификацию

Вход: одна фраза («лендинг для кофейни "Тёплый угол": меню, о нас, отзывы, форма брони»).
Выход: файл `docs/PRD.md` в корне проекта (или рядом с подпроектом, если продукт живёт в подкаталоге).

## Обязательные разделы PRD

1. **Цель** — одно-два предложения: зачем страница/фича существует, какое ОДНО
   целевое действие пользователя.
2. **Аудитория** — 2–3 сегмента с мотивацией (что ищут, что должно убедить).
3. **Стек и ограничения** — конституция: технологии, запреты (lorem, inline-стили,
   лишние библиотеки), язык контента.
4. **Разделы/фичи** — таблица: раздел → идентификатор → задача-слайс. Каждый раздел
   должен нарезаться в отдельную проверяемую задачу.
5. **Контент-принципы** — как звучит текст (оффер вместо приветствия, живые отзывы,
   настоящие названия/цены).
6. **Функциональные требования** — наблюдаемое поведение (валидация, подтверждение,
   навигация), без технических деталей реализации.
7. **Нефункциональные требования** — a11y/SEO/адаптивность, измеримо.
8. **Критерии готовности** — чем ДОКАЗЫВАЕТСЯ готовность: детерминированные гейты,
   вердикты судьи; не «выглядит хорошо».

## Правила

- Каждый пункт критериев — проверяем за <30 секунд командой или взглядом на конкретный элемент.
- Никаких «примерно/красиво/удобно» без измеримой формулировки.
- PRD — источник нарезки задач: раздел без задачи или задача без раздела = дефект спецификации.
