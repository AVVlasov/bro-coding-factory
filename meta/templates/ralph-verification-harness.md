# Ralph Verification Harness — автономная петля верификации (Фазы C–E)

Референс-архитектура и каталог граблей для петли, где кодовый агент делает Фазы 0–B
(исследование/реализация/самопроверка), а обвязка автоматически прогоняет Фазы C–E
(тестеры → детерминированные checks → визуал → судья) и пишет вердикт.

Выстрадано на `samanta_project/ralph` (2026-05-17). Каждая «грабля» ниже — реальный
инцидент с диагнозом и фиксом.

## Когда применять

- В проекте есть ralph-подобный цикл (`loop.ps1`/`loop.sh` + `PROMPT.md` + `STATE.md`),
  и он не доходит до тестеров/судьи или застревает на них.
- Нужно поднять верификацию (тестеры, судья, визуальная проверка) в автономной петле.
- Аудит чужой петли верификации.

## Главный принцип

**Решает агент — исполняет обвязка.** Кодовый агент не вызывает тестеров/судью сам
(в `opencode run` нет ни slash-команд, ни субагентов из `.claude/`). Агент по готовности
кода пишет в маркер-файл *план верификации* (каких тестеров звать, какие команды гонять,
нужен ли визуал), завершает ход — раннер видит маркер и исполняет план отдельным скриптом.

## Компоненты

| Файл | Роль |
|------|------|
| `PROMPT.md` | фикс-промпт итерации; агент делает один шаг Фаз 0–B, затем пишет план |
| `loop.ps1` | раннер: opencode-итерация → backpressure → при маркере зовёт verify-скрипт |
| `verify.ps1` | исполняет план: тестеры (`opencode run`), checks (команды), визуал, судья (`claude -p`) |
| `VERIFY-REQUEST` | маркер с планом (`task:`/`testers:`/`checks:`/`visual:`), пишет агент |
| `STATE.md` | память между итерациями (перезаписывается раннером) — **не источник истины** |
| `tasks/.verdicts/<TASK>.md` | вердикт + `remediation:` — **источник истины**, переживает перезапуск |

Поток: агент (0–B) → пишет `VERIFY-REQUEST` → раннер → `verify.ps1` (C–E) → verdict-файл →
если не `PASS`, ремедиация уходит в `STATE.md` как backpressure → следующая итерация чинит.

## Каталог граблей (симптом → причина → фикс)

| # | Симптом | Причина | Фикс |
|---|---------|---------|------|
| 1 | Фазы C–E недостижимы, агент топчется | `opencode run` не знает `/verify` и субагентов из `.claude/` — они конструкции Claude Code | Фазы C–E исполняет отдельный скрипт-обвязка, а не агент |
| 2 | `Error: Session not found`, итерации вхолостую | Запуск через opencode desktop → дочерний `opencode run` наследует `OPENCODE_*` env со ссылкой на чужую сессию | В начале раннера чистить все `OPENCODE_*` env-переменные |
| 3 | Кириллица в выводе/логе — мусор | Консоль не в UTF-8 (cp866/1251) | `[Console]::OutputEncoding = [Text.Encoding]::UTF8` в начале скриптов |
| 4 | `opencode run` падает: «имя файла слишком длинное» | Промпт (~150–200 КБ) передан аргументом командной строки; лимит Windows ~32 КБ | Подавать промпт через **stdin** (`Get-Content -Raw \| & opencode run …`) |
| 5 | Судья галлюцинирует содержимое файлов | `git diff HEAD` = весь working-tree (сотни файлов); обрезка по лимиту строк выкидывает нужные хунки | Скоуп дифа по файлам из секции «Файлы» task-файла |
| 6 | `diff пуст`, верификация против пустоты | Работа уже закоммичена → `git diff HEAD` пуст | Фоллбэк: если пусто — база `HEAD~1` |
| 7 | Мягкий вердикт, судья пропускает дыры | Слабая модель судьи (напр. minimax) | Судья — на сильной модели (Claude Sonnet/Opus через `claude -p`) |
| 8 | `claude -p --bare` → `Not logged in` | `--bare` отключает не только хуки, но и загрузку авторизации | Не `--bare`, а `--settings '{"disableAllHooks":true}'` |
| 9 | Stop-хуки проекта вмешиваются в прогон судьи | `claude -p` в каталоге проекта грузит хуки из `.claude/settings.json` | `disableAllHooks` через `--settings` |
| 10 | Судья идёт не по той авторизации | В headless `ANTHROPIC_API_KEY` перебивает OAuth-подписку | Перед `claude -p` чистить `ANTHROPIC_API_KEY/AUTH_TOKEN/BASE_URL` |
| 11 | Визуальный тестер виснет (таймаут) | Vision-агент как свободный LLM в `opencode run` пытается сам запускать Electron/скриншоты | Детерминированный vision-сьют (Playwright) снимает PNG, LLM-критик их только **читает** |
| 12 | Негибкий выбор тестеров | Хардкод выбора по regex дифа | План (`testers/checks/visual`) составляет агент в маркере |
| 13 | Задача без зависимостей ложно заблокирована | Gate-парсер выдёргивает любой `TASK-NN` из строки Gate-вход, включая упоминания в прозе | Строку, начинающуюся с «нет», считать отсутствием гейта |
| 14 | При перезапуске агент не устраняет ремедиацию | После стопа раннер затирает `STATE.md` сообщением об остановке; агент читает его, а не вердикт | Агент читает `tasks/.verdicts/<TASK>.md` напрямую — там `remediation:` |
| 15 | Ложный «нет прогресса» на Фазах C–E | Детектор прогресса считает только изменение кода | Verify пишет verdict-файл (вне `ralph/`) — это засчитывается прогрессом |
| 16 | Отчёт агента кончается «Жду „продолжай"» | Интерактивный контракт отчёта применён в автономной петле | В `PROMPT.md` явно запретить эту фразу — следующую итерацию запускает раннер |
| 17 | `File not found: tasks/TASK-NN.md` | Агент конструирует литеральный путь, а у task-файла суффикс-слаг (`TASK-NN-<slug>.md`); слабая модель не разворачивает маску `*` | Раннер пишет точный путь в `CURRENT-FOCUS` (строка `Task file:`); агент читает его, не угадывает имя |

## Контракты

**Маркер `VERIFY-REQUEST`** (пишет агент, формат `ключ: значение`):
```
task: TASK-NN
testers: <список субагентов-тестеров по затронутым слоям>
checks: <детерминированная команда из секции Verify задачи>   # можно несколько строк
visual: yes|no
```

**Verdict-файл `tasks/.verdicts/<TASK>.md`** (пишет verify-скрипт):
```
verdict: PASS | FAIL | NEEDS-MORE-EVIDENCE
diff_fingerprint: <git diff | git hash-object --stdin>
remediation: |
  <шаги для следующей итерации>
```

**Изоляция прогонов:** каждый тестер и судья — отдельный процесс со свежим контекстом;
судья не видел ход реализации, получает только DoD + diff + отчёты тестеров.

## Как применить к новому проекту

1. Убедиться, что в проекте есть ralph-цикл; если нет — перенести `loop.ps1`/`PROMPT.md`.
2. Создать `verify.ps1`: парсинг плана из маркера → тестеры (`opencode run`, stdin) →
   checks (команды) → визуал (детерминированный сьют + LLM-критик) → судья (`claude -p`).
3. Применить ВСЕ фиксы из каталога граблей — большинство (env, кодировка, stdin, скоуп
   дифа) не зависят от проекта.
4. Адаптировать под проект: имена субагентов-тестеров, команды `checks`, путь vision-сьюта.
5. `PROMPT.md`: агент делает Фазы 0–B, пишет план в маркер, читает verdict-файл; без
   интерактивной лексики («жду продолжай»).
6. Проверить РЕАЛЬНЫМ прогоном (не доверять «по аудиту»): синтаксис → dry-run → один
   живой `verify.ps1` end-to-end.

## Анти-паттерны

- Считать петлю рабочей по старому аудиту, не запустив. Каждый фикс выше проверялся прогоном.
- Давать судье слабую модель ради экономии — мягкий вердикт обесценивает гейт.
- Класть в петлю свободный LLM-агент для визуала — детерминированный сьют + критик-чтец.
- Чинить «застряло» снятием защит (no-progress, таймаут) вместо корневой причины.
