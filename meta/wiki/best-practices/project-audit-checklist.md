Проходи по пунктам сверху вниз. Для каждого: ✅ / ❌ / ⚠️ (есть но надо улучшить).

## 1. CLAUDE.md
- [ ] Файл существует в корне проекта
- [ ] Описана роль проекта и контекст для агента
- [ ] Указаны запрещённые действия (что не делать)
- [ ] Описан стек и архитектура (если кодовый проект)
- [ ] Описаны команды сборки/тестов/деплоя

- [ ] Нет устаревших инструкций

## 2. Хуки
- [ ] Хуки описаны в `.claude/settings.json`
- [ ] Pre-tool хук валидирует опасные операции (rm, git reset, etc.)
- [ ] Post-tool хук логирует важные действия (если нужно)
- [ ] Stop-хук сигнализирует о завершении задачи
- [ ] Хуки не дублируют логику друг друга

## 3. Скилы
- [ ] Есть скилы для рутинных задач проекта
- [ ] Скилы задокументированы (что делают, когда триггерить)
- [ ] Нет скилов-зомби (нерабочих или ненужных)

## 4. Субагенты
- [ ] Сложные многошаговые задачи делегируются субагентам
- [ ] Субагенты получают самодостаточный промпт (без зависимости от контекста разговора)
- [ ] Результат субагента проверяется перед применением

## 5. Судьи / Критики
- [ ] Есть судья для критичного вывода (код, документ, план)
- [ ] Судья имеет чёткие критерии оценки (рубрики)
- [ ] Судья независим от агента, которого оценивает

## 6. Настройки (.claude/settings.json)
- [ ] Разрешения (allow/deny) прописаны явно
- [ ] Нет лишних glob-разрешений типа `**/*`
- [ ] Env vars в settings, не в промптах

## 7. Безопасность
- [ ] Секреты не хранятся в CLAUDE.md или промптах
- [ ] Деструктивные операции требуют подтверждения (хук или инструкция)
- [ ] Внешние API вызываются только через явные инструменты

## 8. Документация
- [ ] README актуален
- [ ] Есть описание онбординга для нового разработчика
- [ ] Критичные архитектурные решения задокументированы (ADR или аналог)
